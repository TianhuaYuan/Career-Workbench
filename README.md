# 个人智能求职工作台

基于 Docker 自托管的个人智能求职工作台，围绕 **Job / Application / Resume / Note / Interview** 构建求职业务闭环。项目针对岗位信息分散、简历版本混乱、重复准备成本高及 AI 生成内容可信度不足等问题，将 Agent 能力引入岗位分析、简历定向改写和面试准备。

工作台结合实际投递的简历版本、历史复盘及实时面经生成个性化辅助内容，形成从投递、简历优化到面试复盘的数据闭环。

## 技术栈

**Python / FastAPI / PostgreSQL / pgvector / Redis / MCP / Docker Compose**

## 需求分析与产品规划

梳理岗位记录、简历优化、投递跟踪和面试复盘等核心用户流程，区分传统业务流程与适合 AI 介入的高价值环节，并结合用户价值、使用频率和实现成本确定需求优先级。

对比通用大模型、AI 简历工具、求职管理和面试准备类产品，明确以 **Application** 为业务主线的一体化 AI 求职工作台定位。

## AI 工作流与交互设计

围绕岗位分析、经历匹配、简历改写和面试准备设计 AI 工作流，并针对多版本简历和长期历史数据建立任务级上下文机制。

简历改写采用以下交互流程：

> AI 生成结构化 Diff → 用户确认 → 生成新版本

对重要修改保留人工确认，在提升自动化效率的同时避免 AI 直接覆盖真实业务数据。

## AI 可信度与效果评测

针对多版本数据引用错误、证据不足及模型无依据生成等问题，先通过业务关系限定上下文范围，再结合混合检索与证据校验提升结果的准确性和可追溯性。

构建 **400+ Frozen Eval Case**，并通过 **Bad Case 回归** 持续优化检索、工具调用和模型行为，使固定端到端评测集上的 **Task Success 从约 74% 提升至 81%**。

## 产品指标与落地约束

从效果、时延、成本、隐私和可靠性等维度评估 AI 能力，跟踪任务成功率、无依据生成、调用成本与响应时延等核心指标。

针对长任务中断、外部工具异常、重复执行和高风险操作设计恢复、预算和审批机制，并通过 **Self-hosted、最小必要上下文及外部数据隔离** 降低简历与面试信息的隐私风险。
